**In simple words:** both are token standards on Ethereum, i.e. a common set of functions so that wallets and apps can handle any token. **ERC20** is for tokens where every unit is the same (like rupee notes). **ERC721** is for tokens where every token is unique (like a numbered painting). <Cite id="cryptocurrencies-tokens-gfg-erc-vs" />

| Point | ERC20 | ERC721 |
|---|---|---|
| Type | Fungible (interchangeable) | Non-fungible (unique, NFT) |
| Meaning | One token equals any other | Each token has its own `tokenId` |
| Divisible | Yes, up to `decimals` | No, whole token only |
| Ownership record | Balance of each address | Owner of each token id |
| Main functions | `transfer`, `balanceOf`, `approve`, `transferFrom`, `allowance`, `totalSupply` | `ownerOf`, `safeTransferFrom`, `approve`, `getApproved`, `setApprovalForAll`, `balanceOf` |
| Metadata | Name, symbol, decimals | `tokenURI` points to the image and details |
| Use | Currency, utility, voting, stablecoins | Art, game items, tickets, land deeds |
| Examples | USDT, LINK, UNI | CryptoKitties, Bored Apes |
| EIP | EIP-20 | EIP-721 |

<Cite id="cryptocurrencies-tokens-eip20" /> <Cite id="cryptocurrencies-tokens-eip721" />

**Example:** if you hold 5 ERC20 tokens, you can swap any 2 for someone else's 2 and nothing changes. With ERC721, token #7 and token #8 are different items, so they cannot be swapped like-for-like. <Cite id="cryptocurrencies-tokens-eth-nft" />

**Conclusion:** use ERC20 when units are identical and countable, and ERC721 when each item must be unique.
