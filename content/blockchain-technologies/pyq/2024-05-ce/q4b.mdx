**In simple words:** both `view` and `pure` mark a function that **does not change the blockchain state**. A **view** function may **read** state (storage variables, balances). A **pure** function may **neither read nor change** state; it works only on its own arguments and local variables. <Cite id="solidity-docs-view-pure" />

**Why they are needed:**

1. They tell the reader and the compiler what the function can do. The compiler refuses code that breaks the promise.
2. When called from outside (for example from a web app) as a read-only call, they cost **no gas**, because no transaction is mined. Inside another transaction they still use gas for their computation. <Cite id="solidity-gfg-view-pure" />

**What counts as changing state:** writing to a storage variable, emitting events, creating contracts, sending ether, or calling a non-view function. **What counts as reading state:** reading a storage variable, `address(this).balance`, `block.timestamp`, `msg.sender`, or calling a non-pure function.

**Example:**

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract ViewPureDemo {
    uint public price = 5;

    function setPrice(uint p) public {
        price = p;
    }

    function priceTimes(uint n) public view returns (uint) {
        return price * n;
    }

    function add(uint a, uint b) public pure returns (uint) {
        return a + b;
    }
}
```

**Explanation:** `setPrice` is a normal function: it writes `price`, so it needs a transaction and gas. `priceTimes` is `view` because it reads `price` but does not write it. `add` is `pure` because it uses only `a` and `b`; if it used `price` the compiler would give an error.

<Box kind="verify">

`price` starts at 5. `priceTimes(3)` returns $5 \times 3 = 15$ and leaves `price` unchanged. After `setPrice(8)`, `priceTimes(3)` returns $8 \times 3 = 24$. `add(2, 3)` returns 5 whatever `price` is. Code compiled with solc 0.8.26 without errors.

</Box>

| Point | view | pure |
|---|---|---|
| Reads state | Yes | No |
| Writes state | No | No |
| Uses only arguments and locals | Not necessarily | Yes |
| Example use | Getters, balance checks | Maths helpers, hashing |
| Gas when called off-chain | None | None |

**Conclusion:** use `pure` for plain calculations, `view` for reading data, and neither when the function must change the state. <Cite id="solidity-by-example" />
