**In simple words:** `view` aur `pure` dono aise function mark karte hain jo **blockchain state nahi badalte**. **View** function state **padh** sakta hai (storage variables, balances). **Pure** function state ko **na padh sakta hai na badal sakta hai**; wo sirf apne arguments aur local variables pe kaam karta hai. <Cite id="solidity-docs-view-pure" />

**Kyun zaroori hain:**

1. Ye reader aur compiler ko batate hain ki function kya kar sakta hai. Promise todne wala code compiler reject kar deta hai.
2. Bahar se (jaise web app se) read-only call karne pe inka **gas cost nahi** lagta, kyunki koi transaction mine nahi hota. Kisi aur transaction ke andar inka computation gas use karta hai. <Cite id="solidity-gfg-view-pure" />

**State badalna kya hai:** storage variable mein likhna, events emit karna, contracts banana, ether bhejna, ya non-view function call karna. **State padhna kya hai:** storage variable padhna, `address(this).balance`, `block.timestamp`, `msg.sender`, ya non-pure function call karna.

**Example:**

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract ViewPureDemo {
    uint public price = 5;

    function setPrice(uint p) public {
        price = p;
    }

    function priceTimes(uint n) public view returns (uint) {
        return price * n;
    }

    function add(uint a, uint b) public pure returns (uint) {
        return a + b;
    }
}
```

**Explanation:** `setPrice` normal function hai: `price` mein likhta hai, to transaction aur gas chahiye. `priceTimes` `view` hai kyunki `price` padhta hai lekin likhta nahi. `add` `pure` hai kyunki sirf `a` aur `b` use karta hai; agar `price` use karta to compiler error deta.

<Box kind="verify">

`price` 5 se shuru hota hai. `priceTimes(3)` $5 \times 3 = 15$ return karta hai aur `price` waisa hi rehta hai. `setPrice(8)` ke baad `priceTimes(3)` $8 \times 3 = 24$ deta hai. `add(2, 3)` `price` kuch bhi ho 5 return karta hai. Code solc 0.8.26 se bina error ke compile hua.

</Box>

| Point | view | pure |
|---|---|---|
| State padhta hai | Haan | Nahi |
| State likhta hai | Nahi | Nahi |
| Sirf arguments aur locals | Zaroori nahi | Haan |
| Use | Getters, balance check | Maths helpers, hashing |
| Off-chain call pe gas | Nahi | Nahi |

**Conclusion:** plain calculation ke liye `pure`, data padhne ke liye `view`, aur state badalni ho to dono nahi. <Cite id="solidity-by-example" />

Exam mein English mein likho: "A view function reads state but does not modify it; a pure function neither reads nor modifies state."
