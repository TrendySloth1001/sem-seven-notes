**In simple words:** ERC20 tokens are **interchangeable** like rupee notes (any 10 rupees equals any other 10 rupees). ERC721 tokens are **unique** like a land deed (each one is different). Both are token standards on Ethereum: a fixed list of functions every token contract must offer so wallets and apps can work with it. <Cite id="cryptocurrencies-tokens-eip20" /> <Cite id="cryptocurrencies-tokens-eip721" />

| Point | ERC20 | ERC721 |
|---|---|---|
| Type | Fungible (identical, divisible) | Non-fungible (NFT, unique, indivisible) |
| What is tracked | A balance per address | An owner per token ID |
| Key functions | `transfer`, `balanceOf`, `approve`, `transferFrom`, `allowance` | `ownerOf`, `safeTransferFrom`, `approve`, `getApproved` |
| Divisibility | Yes, using decimals (such as 18) | No, one token is one whole item |
| Uniqueness | None | Each tokenId is different |
| Use cases | Stablecoins, utility tokens, ICO tokens, voting tokens | Digital art, game items, tickets, property deeds |
| Examples | USDT, LINK, UNI | CryptoKitties, Bored Ape NFTs |
| Standard | EIP-20 | EIP-721 |

**Idea in one line each:** in ERC20 the contract keeps `balances[address]`, so "I have 50 tokens". In ERC721 the contract keeps `owner[tokenId]`, so "token 7 belongs to me". <Cite id="cryptocurrencies-tokens-gfg-erc-vs" />

**Conclusion:** use ERC20 when every unit should be the same; use ERC721 when each item must be one of a kind. <Cite id="cryptocurrencies-tokens-eth-erc721" />
