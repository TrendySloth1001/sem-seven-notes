**In simple words:** `view` and `pure` are labels on a function that tell Solidity (and the reader) what the function is allowed to do with the blockchain's data. A function that does not change anything can be called for free from outside, since no transaction is needed. <Cite id="solidity-docs-view-pure" />

**View function:** can **read** state variables but cannot **change** them. Use it for getters.

**Pure function:** can neither read nor change state; it works only on its inputs and local variables. Use it for calculations.

**Normal function:** can read and change state; calling it sends a transaction that costs gas.

| Point | view | pure | Normal |
|---|---|---|---|
| Read state | Yes | No | Yes |
| Change state | No | No | Yes |
| Gas when called from outside | Free | Free | Needs a transaction and gas |
| Typical use | Getters | Maths helpers | Set or update data |

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract ViewPureDemo {
    uint public price = 100;

    // view: reads state, does not change it
    function priceWithTax(uint taxPercent) public view returns (uint) {
        return price + (price * taxPercent) / 100;
    }

    // pure: neither reads nor changes state
    function add(uint a, uint b) public pure returns (uint) {
        return a + b;
    }

    // normal function: changes state, costs gas
    function setPrice(uint newPrice) public {
        price = newPrice;
    }
}
```

**Explanation:** `priceWithTax` uses the state variable `price`, so it must be `view`. `add` uses only its two inputs, so it can be `pure`. `setPrice` writes to `price`, so it can be neither and needs a transaction. If a `view` function tries to write, or a `pure` function tries to read state, the compiler gives an error. <Cite id="solidity-gfg-view-pure" />

<Box kind="verify">

`add(2, 3)` returns 5 with no state used. With `price = 100`, `priceWithTax(10)` gives 100 + (100 x 10) / 100 = 110. After `setPrice(200)`, `priceWithTax(10)` gives 200 + 20 = 220, so the view result follows the state, while `add(2, 3)` is still 5. I compiled this code with solc 0.8.26 without errors.

</Box>

**Conclusion:** use `pure` for calculations, `view` for reading data and normal functions only when state must change. <Cite id="solidity-docs-functions" />
