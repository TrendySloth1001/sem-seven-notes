**In simple words:** the **Flajolet-Martin (FM) algorithm** estimates the number of **distinct** elements in a stream using very little memory. Hash every element to a binary number, count its **trailing zeros** (zeros at the right end), and remember the largest count $R$. The estimate is $2^R$. A hash ending in $r$ zeros has chance $1/2^r$, so seeing $R$ zeros suggests about $2^R$ different elements. Repeats give the same hash, so they never change $R$. <Cite id="stream-counting-fm1985" /> <Cite id="stream-counting-mmds-home" loc="§4.4" /> <Cite id="stream-counting-gfg-fm" />

**Note on the question.** The words "for some a and b" are a leftover from the older version of this question. Here $a = 3$ and $b = 7$ are given, so nothing is unknown. The 5-bit width matters only for the hash value 0, which becomes `00000`.

<Sum>

<Given>

Stream 3, 1, 4, 1, 5, 9, 2, 6, 5. Hash $h(x) = (3x + 7) \bmod 8$, written as a 5-bit binary number.

</Given>

<Find>

the Flajolet-Martin estimate of the number of distinct elements.

</Find>

<Steps>

1. **Hash each element and write it in 5 bits.** *Reason: FM works on the bit pattern of the hash.*

   | $x$ | $3x + 7$ | $h(x) = (3x+7) \bmod 8$ | 5-bit binary | Trailing zeros $r$ |
   |---|---|---|---|---|
   | 3 | 16 | 0 | 00000 | 5 (all bits are 0) |
   | 1 | 10 | 2 | 00010 | 1 |
   | 4 | 19 | 3 | 00011 | 0 |
   | 1 | 10 | 2 | 00010 | 1 |
   | 5 | 22 | 6 | 00110 | 1 |
   | 9 | 34 | 2 | 00010 | 1 |
   | 2 | 13 | 5 | 00101 | 0 |
   | 6 | 25 | 1 | 00001 | 0 |
   | 5 | 22 | 6 | 00110 | 1 |

2. **Maximum tail length.** The hash 0 is `00000`, which has all 5 bits zero, so it counts as 5 trailing zeros. This is the largest, so $R = 5$.
3. **Estimate.** $2^R = 2^5 = 32$.

</Steps>

<Answer>

$R = 5$, so the FM estimate is $2^5 = 32$ distinct elements. The stream really has 7 distinct elements (3, 1, 4, 5, 9, 2, 6). If the all-zero hash is skipped instead (a stated choice), the largest tail is $R = 1$ and the estimate is $2^1 = 2$.

</Answer>

<Box kind="verify">

Check the hashing: $3 \times 3 + 7 = 16 = 2 \times 8$, so $16 \bmod 8 = 0$. $3 \times 1 + 7 = 10$, $10 - 8 = 2$. $3 \times 4 + 7 = 19$, $19 - 16 = 3$. $3 \times 5 + 7 = 22$, $22 - 16 = 6$. $3 \times 9 + 7 = 34$, $34 - 32 = 2$. $3 \times 2 + 7 = 13$, $13 - 8 = 5$. $3 \times 6 + 7 = 25$, $25 - 24 = 1$. Repeats (1 and 5) gave the same hashes (2 and 6), so they did not change $R$. The estimates 32 and 2 are both far from the true count 7, because one hash function on a stream of 9 elements is only a rough guess, and this hash gives only the 8 values 0 to 7. Real use averages many hashes (median of group averages).

</Box>

</Sum>

**Conclusion:** the first element, 3, hashes to 0 and gives the longest tail, so FM estimates $2^5 = 32$ distinct elements (about 2 if that hash is ignored), against the true 7. With a single hash FM is only a rough estimator. <Cite id="stream-counting-wiki-fm" />
