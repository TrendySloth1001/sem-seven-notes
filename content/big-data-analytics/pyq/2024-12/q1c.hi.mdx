**In simple words:** Hadoop sasti machines pe bade files store karne aur batch processing ke liye bahut accha hai, lekin kuch kaamon ke liye galat tool hai. <Cite id="mapreduce-gfg-proscons" />

1. **Small files problem.** NameNode har file aur block ka metadata memory mein rakhta hai, to lakhon chhoti files se uski memory khatam ho jaati hai. HDFS kuch bahut bade files ke liye bana hai. <Cite id="hdfs-apache-design" />
2. **Sirf batch, high latency.** MapReduce job start hone mein seconds se minutes lagte hain, isliye real-time answer ya live streams ke liye nahi chalta.
3. **Iterative kaam mein slow.** Machine learning aur graph algorithms kai baar data pe pass karte hain. MapReduce har job ke baad disk pe likhta hai, to har pass slow hota hai (Spark data memory mein rakhta hai).
4. **Write-once files.** HDFS append allow karta hai lekin random in-place update nahi, to baar-baar badalne wale data ke liye theek nahi. <Cite id="hdfs-apache-design" />
5. **Complex programming.** Raw Java MapReduce mein ek simple join ya multi-step pipeline likhne mein bahut code lagta hai; Hive aur Pig isse chhupane ke liye aaye.
6. **Security default mein weak.** Kerberos khud configure karna padta hai, aur data encrypt nahi hota jab tak set na karein.
7. **Storage overhead.** Three-way replication ka matlab 1 TB data ke liye 3 TB disk.
8. **Single master.** NameNode bottleneck hai aur pehle single point of failure tha; ise hatane ke liye High Availability setup chahiye.

**Conclusion:** Hadoop bade, batch, write-once data ke liye hai. Real-time, iterative ya small-file kaamon ke liye Spark, HBase ya streaming systems use hote hain. <Cite id="hadoop-ecosystem-gfg-hadoop-ecosystem" />

Exam mein English mein likho: "Hadoop is unsuitable for small files, real-time processing and iterative algorithms."
