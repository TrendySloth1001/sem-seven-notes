**In simple words:** SQL databases data ko fixed tables (rows aur columns) mein rakhte hain aur SQL se query karte hain. NoSQL ("not only SQL") databases data ko flexible forms jaise documents, key-value pairs, wide columns ya graphs mein rakhte hain, aur bahut saari sasti machines pe phailne ke liye bane hain. <Cite id="nosql-intro-gfg-sqlvs" /> <Cite id="nosql-intro-ibm-nosql" />

| Point | SQL (relational) | NoSQL |
|---|---|---|
| Data model | Tables with rows and columns | Document, key-value, column-family, graph |
| Schema | Fixed; data se pehle define hota hai | Flexible ya schema-less; har record ke fields alag ho sakte hain |
| Scaling | Mostly vertical (bigger machine) | Horizontal (zyada machines, sharding) |
| Transactions | Strong ACID | Aksar BASE (eventual consistency), kuch ACID bhi dete hain |
| Query language | Standard SQL, powerful joins | Database-specific APIs; joins limited |
| Best for | Structured data, banking, ERP | Huge, varied ya fast-changing data, real-time web apps |
| Examples | MySQL, PostgreSQL, Oracle | MongoDB, Cassandra, Redis, Neo4j |

**Kya choose karein:** jab data structured ho aur har transaction ka sahi hona zaroori ho tab SQL. Jab data huge ho, shape badalta rahe ya bahut servers pe scale karna ho tab NoSQL. Kai systems dono use karte hain. <Cite id="big-data-intro-nosql" />

**Conclusion:** SQL strict structure aur consistency deta hai; NoSQL flexibility aur aasan horizontal scaling deta hai.

Exam mein English mein likho: "SQL is relational with a fixed schema and ACID; NoSQL is non-relational with a flexible schema and scales horizontally."
