**In simple words:** data stream items ka endless flow hai (sensor readings, clicks, tweets). Isspe queries **continuous** hoti hain: ek baar register karo aur naya data aate hi answers milte rehte hain. Ye stored table query karne se bahut mushkil hai. <Cite id="stream-data-model-babcock2002" /> <Cite id="stream-data-model-geisler" />

**Issues aur challenges:**

1. **Unbounded data, limited memory.** Stream kabhi khatam nahi hoti, to sab store nahi ho sakta. Sirf chhota summary rakh sakte hain.
2. **One pass, fast arrival.** Har item ek hi baar dikhta hai aur system rate control nahi kar sakta. Processing speed ke saath chalni chahiye, nahi to items lost ho jaate hain.
3. **Approximate answers.** Kai exact answers (jaise distinct count) ko unbounded memory chahiye. Isliye samples, sketches aur histograms se approximate answers lete hain, known error ke saath.
4. **Blocking operators.** Sort, aggregate aur join ko normally poora input chahiye. Stream pe ye kabhi khatam nahi hote, isliye ye latest items ki **sliding window** pe kaam karte hain. <Cite id="stream-data-model-gfg-dbms-dsms" />
5. **Window aur time handling.** Window size choose karna aur late ya out-of-order items sambhalna mushkil hai.
6. **Bahut saari standing queries.** Sainkdon continuous queries limited CPU aur memory share karti hain. System ko work share karna padta hai aur overload mein **load shedding** (kuch data drop karna) controlled tareeke se karni padti hai.
7. **Past pe ad-hoc queries.** Purana data chala gaya, to uske queries sirf stored summaries se answer hote hain.

**Conclusion:** stream query processing ko ordinary DBMS ke ulat bounded memory, one pass, windows aur approximate answers ke saath kaam karna padta hai.

Exam mein English mein likho: "Stream query processing faces limited memory, one-pass processing, blocking operators, approximate answers and load shedding."
