**In simple words:** NoSQL databases ("not only SQL") became popular because the old relational databases (RDBMS) were hard to stretch for today's data. McCreary and Kelly name four business drivers: **volume, velocity, variability and agility**. <Cite id="big-data-intro-nosql" />

1. **Volume.** Data grew from gigabytes to terabytes and petabytes. A single big server (scale **up**) becomes very costly and has a limit. NoSQL spreads data over many cheap machines (scale **out**), so it can keep growing. <Cite id="nosql-intro-aws-nosql" />
2. **Velocity.** Websites and apps read and write data very fast, and traffic comes in sudden bursts. RDBMS joins and transactions slow down. NoSQL gives fast reads and writes, often by dropping some joins and strict rules. <Cite id="nosql-intro-gfg-intro" />
3. **Variability.** Real data is not neat rows and columns: it is also documents, logs, graphs and sparse records. Adding a column in an RDBMS can mean a table change. NoSQL is flexible about the shape (schema) of data. <Cite id="nosql-intro-ibm-nosql" />
4. **Agility.** Teams want to release features quickly. Object-relational mapping and fixed schemas slow them down. A document or key-value store lets the program's data structure be saved almost as it is, so changes are faster.

| Driver | Problem with RDBMS | NoSQL answer |
|---|---|---|
| Volume | Scale-up is costly and limited | Scale-out on commodity servers |
| Velocity | Joins and locks slow writes | Fast simple reads and writes |
| Variability | Fixed schema | Flexible schema |
| Agility | Slow to change | Easy to change and release |

**Conclusion:** NoSQL grew because businesses needed to store more, faster and more varied data at lower cost, and to change their applications quickly.
