**In simple words:** NoSQL databases ("not only SQL") isliye popular hue kyunki purane relational databases (RDBMS) aaj ke data ke liye stretch karna mushkil tha. McCreary aur Kelly chaar business drivers batate hain: **volume, velocity, variability aur agility**. <Cite id="big-data-intro-nosql" />

1. **Volume.** Data gigabytes se terabytes aur petabytes tak pahunch gaya. Ek badi server (scale **up**) bahut mehngi hoti hai aur uski limit hoti hai. NoSQL data ko kai sasti machines pe failata hai (scale **out**), to data badhta reh sakta hai. <Cite id="nosql-intro-aws-nosql" />
2. **Velocity.** Websites aur apps bahut tez read aur write karte hain, aur traffic achanak bursts mein aata hai. RDBMS ke joins aur transactions slow ho jaate hain. NoSQL fast reads aur writes deta hai, aksar kuch joins aur strict rules chhod kar. <Cite id="nosql-intro-gfg-intro" />
3. **Variability.** Asli data neat rows aur columns jaisa nahi hota: documents, logs, graphs aur sparse records bhi hote hain. RDBMS mein column add karna matlab table change. NoSQL data ki shape (schema) mein flexible hai. <Cite id="nosql-intro-ibm-nosql" />
4. **Agility.** Teams ko features jaldi release karne hote hain. Object-relational mapping aur fixed schemas unhe slow karte hain. Document ya key-value store mein program ka data structure lagbhag jaisa hai waisa save ho jaata hai, to changes tez hote hain.

| Driver | Problem with RDBMS | NoSQL answer |
|---|---|---|
| Volume | Scale-up costly aur limited | Scale-out on commodity servers |
| Velocity | Joins aur locks writes slow karte hain | Fast simple reads aur writes |
| Variability | Fixed schema | Flexible schema |
| Agility | Change karna slow | Change aur release karna easy |

**Conclusion:** NoSQL isliye bada kyunki businesses ko zyada, tez aur alag-alag tarah ka data kam cost mein store karna tha, aur apni applications jaldi badalni thi.

Exam mein English mein likho: "The core business drivers of NoSQL are volume, velocity, variability and agility."
