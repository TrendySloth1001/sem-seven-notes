**In simple words:** a **Map task** reads one chunk (split) of the input, one record at a time, and turns every record into zero or more **(key, value)** pairs. It is the "sort the raw data into labelled piles" step, and many map tasks run in parallel on different machines, each on the data stored near it. <Cite id="hadoop-ecosystem-dean2004" /> <Cite id="mapreduce-gfg-mr" />

**Function of a map task**

1. **Read:** take one input split (for example one HDFS block) and read it record by record.
2. **Apply the user's map function** to each record and emit intermediate `(key, value)` pairs.
3. **Partition and sort:** the pairs are split by key into one part per reducer and sorted by key.
4. **Spill:** the result is written to the local disk of that machine (not to HDFS), ready for the shuffle. <Cite id="hadoop-ecosystem-apache-mr-tutorial" />

**Example (word count).** Two splits go to two map tasks. The map function emits `(word, 1)` for every word.

| Map task | Input split | Map output |
|---|---|---|
| M1 | red blue red | (red,1) (blue,1) (red,1) |
| M2 | blue green | (blue,1) (green,1) |

The shuffle later brings all pairs of one key together, so the reducer can add them: red 2, blue 2, green 1. <Cite id="mapreduce-av" />

**Points to remember:** a map task works on one record at a time, needs no other map task, and if it fails only that task is re-run. A map task never combines results of different splits; that is the reducer's job.
