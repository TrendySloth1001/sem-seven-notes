**In simple words:** **Map task** input ka ek chunk (split) leta hai, ek-ek record padhta hai, aur har record ko zero ya zyada **(key, value)** pairs mein badal deta hai. Ye "raw data ko labelled piles mein sort karna" wala step hai. Bahut saare map tasks alag machines pe parallel chalte hain, har ek apne paas rakhe data pe. <Cite id="hadoop-ecosystem-dean2004" /> <Cite id="mapreduce-gfg-mr" />

**Map task ka function**

1. **Read:** ek input split (jaise ek HDFS block) lo aur record by record padho.
2. **User ka map function lagao** har record pe aur intermediate `(key, value)` pairs emit karo.
3. **Partition aur sort:** pairs ko key ke hisaab se reducers ke liye baanto aur key se sort karo.
4. **Spill:** result us machine ki local disk pe likha jaata hai (HDFS pe nahi), shuffle ke liye ready. <Cite id="hadoop-ecosystem-apache-mr-tutorial" />

**Example (word count).** Do splits do map tasks ko jaate hain. Map function har word ke liye `(word, 1)` emit karta hai.

| Map task | Input split | Map output |
|---|---|---|
| M1 | red blue red | (red,1) (blue,1) (red,1) |
| M2 | blue green | (blue,1) (green,1) |

Shuffle baad mein ek key ke saare pairs ek jagah laata hai, to reducer unhe add kar sakta hai: red 2, blue 2, green 1. <Cite id="mapreduce-av" />

**Yaad rakhne ki baatein:** map task ek time pe ek record pe kaam karta hai, kisi aur map task pe depend nahi karta, aur fail ho jaye to sirf wahi task dobara chalta hai. Alag splits ke results ko jodna map task ka kaam nahi, wo reducer ka kaam hai.

Exam mein English mein likho: "A map task reads an input split and emits intermediate key-value pairs."
