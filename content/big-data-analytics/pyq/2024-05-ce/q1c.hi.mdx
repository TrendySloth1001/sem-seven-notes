**In simple words:** NoSQL ("not only SQL") databases data ko relational database ke fixed tables aur joins ke bina store karte hain. McCreary aur Kelly chaar business drivers batate hain jinki wajah se companies NoSQL ki taraf gayi: **volume, velocity, variability aur agility**. <Cite id="big-data-intro-nosql" /> <Cite id="nosql-intro-ibm-nosql" />

1. **Volume.** Data itna badh gaya ki ek bade server mein nahi aata. Bada server kharidna (scale up) bahut mehnga padta hai, isliye firms bahut saare sasti servers jodna (scale out) pasand karti hain. Relational databases scale out mein weak hain kyunki machines ke beech joins aur transactions slow hote hain. NoSQL cluster pe data failane ke liye bana hai.
2. **Velocity.** Websites pe ab har second bahut saare reads aur writes aate hain, aur data lagatar aata rehta hai. NoSQL stores thodi strict consistency chhod ke bahut fast reads aur writes dete hain.
3. **Variability.** Real data ek fixed shape mein nahi aata: har customer ya product ke alag fields ho sakte hain. Badi relational table mein column add karna mushkil hai. NoSQL (key-value, document, column family, graph) flexible schema deta hai.
4. **Agility.** Business aur developers ko application jaldi badalni hoti hai. Objects ko tables se map karna, schema changes aur DBA approvals teams ko slow karte hain. Poore object ko ek document mein store karne se ye mapping khatam hoti hai aur release tez hoti hai.

| Driver | Relational ki dikkat | NoSQL ka jawab |
|---|---|---|
| Volume | Mehnga scale up | Commodity servers pe scale out |
| Velocity | Machines ke beech slow writes | Fast reads aur writes, relaxed consistency |
| Variability | Fixed schema | Flexible schema |
| Agility | Mapping aur schema changes | Object ko jaisa hai waisa store karo |

**Conclusion:** NoSQL tab chuna jaata hai jab business ko huge size, fast access, badalti data shapes aur tez development chahiye. <Cite id="nosql-intro-gfg-sqlvs" />
