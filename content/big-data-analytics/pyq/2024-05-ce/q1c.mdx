**In simple words:** NoSQL ("not only SQL") databases store data without the fixed tables and joins of a relational database. McCreary and Kelly name four business drivers that pushed companies to NoSQL: **volume, velocity, variability and agility**. <Cite id="big-data-intro-nosql" /> <Cite id="nosql-intro-ibm-nosql" />

1. **Volume.** Data grew far beyond what one big server can hold. Buying a bigger server (scale up) gets very costly, so firms prefer adding many cheap servers (scale out). Relational databases scale out poorly because joins and transactions across machines are slow. NoSQL is built to spread data over a cluster.
2. **Velocity.** Websites now take huge numbers of reads and writes per second, and the data arrives continuously. NoSQL stores trade some strict consistency for very fast reads and writes.
3. **Variability.** Real data does not fit one fixed shape: every customer or product may have different fields. Adding a column to a big relational table is painful. NoSQL (key-value, document, column family, graph) allows a flexible schema.
4. **Agility.** Business and developers need to change the application quickly. Mapping objects to tables, schema changes and DBA approvals slow teams down. Storing a whole object as one document removes that mapping and speeds up releases.

| Driver | Relational pain | NoSQL answer |
|---|---|---|
| Volume | Costly scale up | Scale out on commodity servers |
| Velocity | Slow cross-machine writes | Fast reads and writes, relaxed consistency |
| Variability | Fixed schema | Flexible schema |
| Agility | Mapping and schema changes | Store the object as is |

**Conclusion:** NoSQL is chosen when the business needs huge size, fast access, changing data shapes and quick development. <Cite id="nosql-intro-gfg-sqlvs" />
