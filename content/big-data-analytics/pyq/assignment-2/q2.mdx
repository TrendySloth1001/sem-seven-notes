**In simple words:** DGIM counts the 1s in the last $N$ bits of a stream by keeping a few buckets. A bucket is written (size, timestamp of its right end), where size is the number of 1s it covers. The buckets must follow these rules. <Cite id="stream-counting-mmds-home" loc="§4.6" />

**Constraints for bucket creation:**

1. **Right end is a 1.** The timestamp of a bucket marks a real 1.
2. **Every 1 is in a bucket,** so no 1 is left uncounted.
3. **No position is in more than one bucket,** so no 1 is counted twice.
4. **One or two buckets of each size,** up to some maximum size. This keeps the number of buckets small.
5. **Sizes are powers of 2** (1, 2, 4, 8, ...), so there are only about $\log N$ different sizes.
6. **Sizes never decrease going to the left (back in time).** Recent 1s are known exactly; only old ones are rough.
7. **A bucket disappears** when its right end is entirely out of the window of the last $N$ bits. <Cite id="stream-counting-wiki-dsm" />

**Example:** the stream 1 1 1 at times 1, 2, 3 first gives three size-1 buckets. Rule 4 is broken, so the two oldest merge into (size 2, timestamp 2). The buckets are now (2, t=2) and (1, t=3): one of each size, older bucket larger, all rules hold.

**Extend in the exam (add these if the question carries more marks):**

- **How a count is answered.** To count the 1s in the last $k$ bits, add the sizes of all buckets inside the range except the oldest one, then add half the size of the oldest bucket (it may be only partly inside). <Cite id="stream-counting-mmds-home" loc="§4.6" />
- **Why the error is small.** Only the oldest bucket is uncertain, and it is at most as big as the sum of the others, so the answer is within 50 percent of the true count.
- **Memory used.** About $\log N$ buckets, each needing about $\log N$ bits, so roughly $(\log N)^2$ bits instead of $N$ bits. <Cite id="stream-counting-cs246-slides" />
- **Update rule.** When a new 1 arrives, make a size-1 bucket; if there are now three buckets of one size, merge the two oldest into a bucket of double size, and repeat for the next size up.

**Conclusion:** these rules keep only about $\log N$ buckets and let DGIM answer the count within 50 percent error. <Cite id="stream-counting-cs246-slides" />
