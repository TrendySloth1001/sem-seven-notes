**In simple words:** a content-based recommender suggests items that are similar to the items a user liked before. "Similar" is judged from the item's own properties, such as genre or important words, not from other users. <Cite id="recommendation-systems-mmds-book" loc="Ch. 9" /> <Cite id="recommendation-systems-google-cb" />

1. **Item profile.** Describe each item by a vector of features: a movie by genre, director and actors (1 = has it, 0 = does not); a text by its important words using TF-IDF.
   **Example:** a movie is Action = 1, Sci-fi = 1, Romance = 0.
2. **TF-IDF for text.** TF is how often a word appears in this item; IDF is $\log_2(N/n_i)$, how rare the word is across all $N$ items. A word with high TF and high IDF describes the item well. A word in every item has IDF 0. <Cite id="recommendation-systems-wiki-tfidf" />
3. **User profile.** Average the profiles of the items the user liked. <Cite id="web-bda-2-mmds-recsys" loc="slides 15-17" />
4. **Match with cosine similarity.** $\cos(u,i) = \dfrac{u\cdot i}{\lVert u\rVert\lVert i\rVert}$ between the user profile and each unseen item.
5. **Recommend** the top-scoring unseen items.

**Case study: a Netflix-style movie service.** The service describes movies by genres and tags, in the same way as the MovieLens tag genome. <Cite id="recommendation-systems-wiki-genome" /> A user watched and liked M1 and M2.

| Movie | Action | Sci-fi | Romance | Status |
|---|---|---|---|---|
| M1 | 1 | 1 | 0 | liked |
| M2 | 1 | 0 | 0 | liked |
| M3 | 0 | 0 | 1 | unseen |
| M4 | 1 | 1 | 1 | unseen |
| M5 | 0 | 1 | 0 | unseen |

<Sum>

<Given>

The feature table above.

</Given>

<Find>

which unseen movie to recommend first.

</Find>

<Steps>

1. **User profile** $= \frac{M1 + M2}{2} = (1, 0.5, 0)$, length $\sqrt{1+0.25} = 1.118$. *Reason: the user likes Action always and Sci-fi half the time.*
2. **M3:** dot $= 0$, so cosine $= 0$.
3. **M4:** dot $= 1 + 0.5 + 0 = 1.5$; length $\sqrt{3} = 1.732$; cosine $= 1.5/(1.118 \times 1.732) = 0.775$.
4. **M5:** dot $= 0.5$; length $1$; cosine $= 0.5/1.118 = 0.447$.

</Steps>

<Answer>

Recommend **M4** first (0.775), then M5 (0.447); M3 (0) is not recommended.

</Answer>

<Box kind="verify">

M4 shares both the Action and Sci-fi tastes of the user, M5 shares only Sci-fi, and M3 shares nothing, so the order M4, M5, M3 matches common sense.

</Box>

</Sum>

**Extend in the exam (add these to reach 10 marks):**

- **Justification: why use it.** It needs no data about other users, so it works for a new movie with no ratings, and it can explain "recommended because you liked Action and Sci-fi". <Cite id="recommendation-systems-gfg-cb" />
- **Limitation: over-specialisation.** It keeps recommending the same kind of item and rarely surprises the user.
- **Limitation: cold start for a new user and need for good features.** With no liked items there is no profile, and poor tags give poor matches.
- **Comparison with collaborative filtering.** Content-based uses item features; collaborative filtering uses what similar users liked, so it can suggest a surprise but cannot handle a new item with no ratings.
- **Other uses.** News articles (TF-IDF words), music tracks, books and job postings.

**Conclusion:** content-based recommendation is justified where items have good descriptions, because it recommends items matching a user's own tastes without needing other users.
