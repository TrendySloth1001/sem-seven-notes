**In simple words:** SQL databases data ko fixed structure wale tables mein rakhte hain aur SQL se query karte hain. NoSQL ("not only SQL") databases data ko key-value pairs, documents, column families ya graphs ki tarah rakhte hain, structure flexible hota hai, aur ye bahut saste servers pe scale out karne ke liye bane hain. <Cite id="nosql-intro-gfg-sqlvs" /> <Cite id="nosql-intro-ibm-nosql" />

| Point | SQL (relational) | NoSQL |
|---|---|---|
| Data model | Rows aur columns ke tables | Key-value, document, column family ya graph |
| Schema | Pehle se fixed; badalna slow | Flexible ya schema-less; har record alag ho sakta hai |
| Query language | SQL, sab products mein same | Common language nahi; har product ka apna API |
| Scaling | Mainly scale up (bada server) | Scale out (zyada saste servers) |
| Transactions | Full ACID | Aksar limited ACID; kai BASE (eventual consistency) use karte hain |
| Joins | Strong support | Weak ya nahi; related data saath rakha jaata hai |
| Best for | Strict correctness wala structured data (banking) | Huge, fast, varied data (social media, logs, catalogues) |
| Examples | MySQL, Oracle, PostgreSQL | MongoDB, Cassandra, Redis, Neo4j |

<Cite id="nosql-intro-aws-nosql" />

**Conclusion:** koi bhi hamesha better nahi hai. Kai systems dono use karte hain, ise polyglot persistence kehte hain: payments ke liye SQL, product catalogue aur sessions ke liye NoSQL. <Cite id="nosql-intro-fowler-poly" />

Exam mein English mein likho: "SQL is relational, schema-fixed and ACID. NoSQL is non-relational, schema-flexible and scales out."
