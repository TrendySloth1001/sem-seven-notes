**In simple words:** Hadoop is an open-source framework that stores big data across many ordinary computers (HDFS) and processes it in parallel (MapReduce, with YARN to share the cluster). It is very good at some jobs and poor at others. <Cite id="hadoop-ecosystem-gfg-hadoop-intro" /> <Cite id="hadoop-ecosystem-wiki-hadoop" />

**Advantages**

1. **Scalable:** add more machines to grow from a few nodes to thousands.
2. **Low cost:** cheap commodity hardware and free software.
3. **Fault tolerant:** every block is copied to 3 nodes by default, and failed tasks are re-run on another node.
4. **Any data type:** structured, semi-structured and unstructured, with schema applied on read.
5. **Fast on huge data:** data locality (the program runs where the data is) and parallel work give high throughput.
6. **Big ecosystem:** Hive, Pig, HBase, Spark and many more tools.

**Limitations**

1. **Small files:** every file and block takes NameNode memory, so millions of tiny files overload it.
2. **Batch only:** jobs take seconds to minutes, so it is unsuitable for real-time answers.
3. **Slow for iterative work:** MapReduce writes to disk between steps, which hurts machine learning and graph loops (Spark fixes this with memory).
4. **No in-place update or transactions:** HDFS is write-once, read-many.
5. **Hard programming:** plain MapReduce needs long Java code.
6. **NameNode weak point and 3x storage cost:** a standby NameNode needs extra setup, and three copies triple disk use.

<Cite id="mapreduce-gfg-proscons" /> <Cite id="hadoop-ecosystem-ibm-hadoop" />

**Conclusion:** use Hadoop for cheap, large, batch analysis. Do not use it for small data, real-time queries or banking-style transactions.
