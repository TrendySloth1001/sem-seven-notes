**In simple words:** traditional data is small, neat, table-shaped data that one database server can store and process. Big data is so large, so fast and so mixed that one server cannot cope, so it is spread over a cluster of cheap computers. <Cite id="big-data-intro-oracle" /> <Cite id="big-data-intro-gfg" />

| Point | Traditional data | Big data |
|---|---|---|
| Size | Megabytes to a few terabytes | Terabytes to petabytes and more |
| Type | Mostly structured (tables) | Structured, semi-structured and unstructured |
| Schema | Fixed before storing (schema-on-write) | Flexible, applied when read (schema-on-read) |
| Growth | Slow and predictable | Fast and continuous |
| Scaling | Scale up: a bigger, costlier server | Scale out: add many cheap nodes |
| Processing | One machine; data moves to the program | Cluster; the program moves to the data |
| Arrival | Mostly batch updates | Batch and real-time streams |
| Tools | RDBMS, SQL, data warehouse | Hadoop, Spark, NoSQL, Kafka |
| Failure | Server failure is serious | Node failure is expected and handled by copies |
| Cost | Costly hardware and licences | Cheap hardware, often open source |

<Cite id="big-data-intro-av" /> <Cite id="big-data-intro-mmds" />

**Example:** a college fee register is traditional data. Every click, video and post of a social media app is big data.

**Conclusion:** the difference is not only size. Big data also has high speed and many formats, so it needs distributed tools instead of a single database server.
