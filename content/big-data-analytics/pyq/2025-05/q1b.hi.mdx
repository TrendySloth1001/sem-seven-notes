**In simple words:** Hadoop ek open-source framework hai jo big data ko bahut saare normal computers pe store karta hai (HDFS) aur parallel process karta hai (MapReduce, aur cluster share karne ke liye YARN). Kuch kaam mein ye bahut accha hai, kuch mein kamzor. <Cite id="hadoop-ecosystem-gfg-hadoop-intro" /> <Cite id="hadoop-ecosystem-wiki-hadoop" />

**Advantages**

1. **Scalable:** machines jodte jao, kuch nodes se hazaaron nodes tak badh sakta hai.
2. **Low cost:** saste commodity hardware aur free software.
3. **Fault tolerant:** har block default mein 3 nodes pe copy hota hai, aur fail hue task dusre node pe dobara chalte hain.
4. **Kisi bhi type ka data:** structured, semi-structured aur unstructured, schema read karte time lagta hai.
5. **Huge data pe fast:** data locality (program wahan chalta hai jahan data hai) aur parallel kaam se high throughput milta hai.
6. **Bada ecosystem:** Hive, Pig, HBase, Spark aur bahut saare tools.

**Limitations**

1. **Small files:** har file aur block NameNode ki memory leta hai, to lakhon chhoti files se NameNode overload ho jaata hai.
2. **Sirf batch:** jobs ko seconds se minutes lagte hain, to real-time answers ke liye theek nahi.
3. **Iterative kaam mein slow:** MapReduce steps ke beech disk pe likhta hai, jo machine learning aur graph loops ko slow karta hai (Spark memory use karke ye theek karta hai).
4. **In-place update ya transactions nahi:** HDFS write-once, read-many hai.
5. **Programming mushkil:** plain MapReduce mein lamba Java code likhna padta hai.
6. **NameNode weak point aur 3x storage cost:** standby NameNode ke liye extra setup chahiye, aur teen copies se disk teen guna lagti hai.

**Conclusion:** Hadoop ko sasta, bada, batch analysis ke liye use karo. Chhote data, real-time queries ya banking jaise transactions ke liye use mat karo.
