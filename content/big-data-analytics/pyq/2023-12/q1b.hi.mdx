**In simple words:** traditional database structured data ko ek strong server pe tables mein rakhta hai. Big data itna bada, tez aur mixed hota hai ki use bahut si machines milke handle karti hain. <Cite id="big-data-intro-oracle" /> <Cite id="big-data-intro-av" />

| Point | Traditional database | Big data |
|---|---|---|
| Size | Megabytes to a few terabytes. | Terabytes to petabytes and more. |
| Data type | Mostly structured (tables). | Structured, semi-structured and unstructured. |
| Schema | Fixed before storing (schema-on-write). | Flexible, applied when reading (schema-on-read). |
| Growth | Slow and predictable. | Fast and continuous. |
| Scaling | Scale up: bigger, costlier server. | Scale out: many cheap nodes. |
| Processing | One machine; data program ke paas laaya jaata hai. | Cluster; program data ke paas bheja jaata hai. |
| Arrival | Mostly batch updates. | Batch and real-time streams. |
| Tools | RDBMS, SQL, data warehouse. | Hadoop, Spark, NoSQL, Kafka. |
| Failure | Server failure serious hai. | Node failure expected hai, copies se handle hota hai. |
| Cost | Costly hardware and licences. | Cheap hardware, often open source. |

<Cite id="big-data-intro-mmds" /> <Cite id="big-data-intro-gfg" />

**Example.** College fee record traditional database mein fit ho jaata hai. Millions of users ke clicks, videos aur sensor readings ke liye big data tools chahiye.

**Conclusion:** chhota, structured, transactional data traditional database ke liye best hai; jab volume, velocity aur variety ek machine se bahar ho tab big data systems chahiye.
