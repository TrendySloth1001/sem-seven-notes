**In simple words:** **DGIM** (Datar, Gionis, Indyk, Motwani) 0/1 stream ke last $N$ bits mein 1s ginta hai, bits ko store kiye bina. Ye sirf kuch **buckets** rakhta hai. Har bucket apna **size** (kitne 1s cover karta hai) aur **right (newest) end ka timestamp** store karta hai. Bucket list tabhi valid hai jab wo in rules ko follow kare. <Cite id="stream-counting-mmds-home" loc="§4.6" /> <Cite id="stream-counting-wiki-dsm" />

1. **Har bucket ka right end ek 1 hota hai.** Bucket kabhi 0 par khatam nahi hota.
2. **Koi position ek se zyada bucket mein nahi hoti.** Buckets overlap nahi karte.
3. **Har size ke ek ya do buckets hote hain**, ek maximum size tak. Ek size ke teen ho jaayein to merge karna padta hai.
4. **Har size 2 ki power hota hai** (1, 2, 4, 8, ...). Size 3 ka bucket allowed nahi.
5. **Peeche jaate hue sizes kam nahi hote.** Newest se oldest ki taraf sizes same rehte hain ya badhte hain.

(Poori list mein ye bhi aata hai ki window ka har 1 kisi bucket mein hota hai, aur bucket tab hata diya jaata hai jab uska right end window ke bahar chala jaaye.) <Cite id="stream-counting-cs246-slides" />

**Example.** Ek valid list, newest pehle, (size, right-end timestamp) ke roop mein: (1, 50), (1, 48), (2, 45), (4, 38), (4, 30). Sizes 1, 1, 2, 4, 4 sab 2 ki power hain, har size ke zyada se zyada do, aur kam nahi hote.

| Invalid list (sizes, newest pehle) | Kaunsa rule tuta |
|---|---|
| 1, 2, 2, 2, 4 | Size 2 ke teen buckets (rule 3) |
| 1, 3, 4 | 3, 2 ki power nahi hai (rule 4) |
| 2, 1, 1 | Purana bucket chhota hai (rule 5) |

**Conclusion:** ye rules memory chhoti rakhte hain (lagbhag $O(\log^2 N)$ bits) aur count ko asli value ke 50 percent ke andar rakhte hain.

Exam mein English mein likho: "In DGIM every bucket ends in a 1, buckets do not overlap, there are one or two buckets of each size, sizes are powers of 2, and sizes do not decrease going back in time."
