**In simple words:** a **business driver** is a business need that pushes a company to change its technology. McCreary and Kelly list four that pushed companies from relational databases (RDBMS) to NoSQL. <Cite id="big-data-intro-nosql" />

1. **Volume.** Data grows from gigabytes to terabytes and more (clicks, sensors, posts). One server has a limit and a bigger one costs far more, so NoSQL **scales out** over many cheap machines instead of scaling up.
2. **Velocity.** Data arrives and is read very fast, with sudden bursts of users (a sale, a viral post). Strict locking and joins slow an RDBMS down, so NoSQL uses simple access by key, spreads data over nodes and relaxes consistency.
3. **Variability.** Records have different shapes: some have fields others lack, and new fields appear often. An RDBMS forces a fixed schema with many empty columns, while NoSQL allows a flexible, schema-less record.
4. **Agility.** Teams must release features quickly. Mapping objects in code to tables and changing the schema slows developers, so NoSQL stores the object as it is (for example a JSON document). <Cite id="nosql-intro-fowler-agg" />

| Driver | Pressure on the business | NoSQL answer |
|---|---|---|
| Volume | Huge data | Scale out |
| Velocity | Fast reads and writes | Key access, distributed data |
| Variability | Different data shapes | Flexible schema |
| Agility | Quick changes | Store the object as it is |

<Cite id="nosql-intro-ibm-nosql" /> <Cite id="nosql-intro-gfg-intro" />

**Conclusion:** volume and velocity are about size and speed; variability and agility are about change. Together they made companies choose NoSQL.
