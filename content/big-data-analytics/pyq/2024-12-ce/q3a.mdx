**In simple words:** a MapReduce job runs in a fixed pipeline. The input is split, **map** tasks turn each split into `(key, value)` pairs, the pairs are grouped by key (**shuffle**), and **reduce** tasks combine each group into the final answer. <Cite id="mapreduce-gfg-mr" /> <Cite id="hadoop-ecosystem-dean2004" />

```mermaid
%% caption: MapReduce execution pipeline. Map output is combined, partitioned and sorted on local disk. Each reducer copies its own part from every mapper (the shuffle), then writes its result to HDFS.

  C2 --> SH
  SH --> R1["Reduce task: merge, reduce"]
  R1 --> O1["Output file in HDFS"]
```

**Steps of execution.** <Cite id="mapreduce-tp" /> <Cite id="hadoop-ecosystem-apache-mr-tutorial" />

1. **Submit.** The client submits the job; the cluster manager starts a job master.
2. **Split.** The input is cut into splits, one map task per split, placed near the data.
3. **Map.** Each map task reads its records and emits `(key, value)` pairs.
4. **Combine, partition, sort.** An optional combiner adds up pairs locally. A partitioner decides the reducer for each key, $\text{hash}(key) \bmod R$.
5. **Shuffle.** Each reducer copies its part from every mapper.
6. **Reduce.** The reducer merges the keys into sorted groups and runs reduce on each. It starts only after all maps finish.
7. **Output.** Results are written to HDFS, one file per reducer.

<Sum>

<Given>

Word count with a combiner and one reducer. Split 1: "big data big". Split 2: "data big tools".

</Given>

<Find>

the output of each stage.

</Find>

<Steps>

1. **Map.** Split 1: (big,1) (data,1) (big,1). Split 2: (data,1) (big,1) (tools,1).
2. **Combiner.** Split 1: (big,2) (data,1). Split 2 has no repeat, so it stays. Pairs to shuffle: $2 + 3 = 5$ instead of 6.
3. **Shuffle and sort.** big: [2, 1], data: [1, 1], tools: [1].
4. **Reduce.** Add each list.

</Steps>

<Answer>

big 3, data 2, tools 1.

</Answer>

<Box kind="verify">

The input has 6 words and $3 + 2 + 1 = 6$. Direct count: big appears 2 times in split 1 and once in split 2, which is 3.

</Box>

</Sum>

**Conclusion:** the framework handles splitting, scheduling, shuffle and failures, so the programmer writes only map and reduce.
