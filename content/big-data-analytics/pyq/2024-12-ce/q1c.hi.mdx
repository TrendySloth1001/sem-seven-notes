**In simple words:** **business driver** matlab business ki wo zaroorat jo company ko apni technology badalne par majboor karti hai. McCreary aur Kelly ne chaar drivers bataye hain jinki wajah se companies relational database (RDBMS) se NoSQL ki taraf gayi. <Cite id="big-data-intro-nosql" />

1. **Volume.** Data gigabytes se terabytes aur usse bhi zyada ho jaata hai (clicks, sensors, posts). Ek server ki limit hoti hai aur bada server bahut mehenga padta hai, isliye NoSQL bahut saari sasti machines par **scale out** karta hai.
2. **Velocity.** Data bahut tez aata hai aur tez padha jaata hai, users ki achanak bheed bhi aati hai (sale, viral post). Strict locking aur joins RDBMS ko slow kar dete hain, isliye NoSQL key se simple access, data ko nodes mein baatna aur consistency thodi relax karna use karta hai.
3. **Variability.** Records ki shape alag-alag hoti hai: kisi mein wo fields hote hain jo dusre mein nahi, aur nayi fields aati rehti hain. RDBMS fixed schema aur bahut saare empty columns maangta hai, jabki NoSQL flexible, schema-less record deta hai.
4. **Agility.** Teams ko features jaldi release karne hote hain. Code ke objects ko tables se map karna aur schema badalna developers ko slow karta hai, isliye NoSQL object ko jaisa hai waisa store karta hai (jaise JSON document). <Cite id="nosql-intro-fowler-agg" />

| Driver | Business par pressure | NoSQL ka jawab |
|---|---|---|
| Volume | Bahut bada data | Scale out |
| Velocity | Tez reads aur writes | Key access, distributed data |
| Variability | Alag-alag data shapes | Flexible schema |
| Agility | Jaldi changes | Object jaisa hai waisa store |

<Cite id="nosql-intro-ibm-nosql" /> <Cite id="nosql-intro-gfg-intro" />

**Conclusion:** volume aur velocity size aur speed ke baare mein hain; variability aur agility change ke baare mein. In sabne milkar companies ko NoSQL ki taraf dhakela.

Exam mein English mein likho: "The core business drivers behind NoSQL are volume, velocity, variability and agility."
