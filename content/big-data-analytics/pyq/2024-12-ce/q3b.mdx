**In simple words:** a **Bloom filter** is a bit array with several hash functions. To **insert** an element, set the bits at its hash positions to 1. To **check** an element, look at its positions: if any bit is 0 it is **definitely not** in the set; if all are 1 it is **probably** in the set. <Cite id="stream-counting-wiki-bloom" /> <Cite id="stream-counting-gfg-bloom" />

<Sum>

<Given>

$m = 8$ bits, all 0 at the start (positions 0 to 7). $h_1(x) = x \bmod 8$, $h_2(x) = (2x+1) \bmod 8$, $h_3(x) = (3x+2) \bmod 8$. Insert 12, 25, 30, 5. Check 6 and 55.

</Given>

<Find>

the final bit array, whether 6 and 55 are reported present, and which results are right.

</Find>

<Steps>

1. **Hash each element.** *Reason: these are the bit positions it will set.*

   | $x$ | $h_1$ | $h_2$ | $h_3$ | Bits set |
   |---|---|---|---|---|
   | 12 | $12 \bmod 8 = 4$ | $25 \bmod 8 = 1$ | $38 \bmod 8 = 6$ | 1, 4, 6 |
   | 25 | $25 \bmod 8 = 1$ | $51 \bmod 8 = 3$ | $77 \bmod 8 = 5$ | 1, 3, 5 |
   | 30 | $30 \bmod 8 = 6$ | $61 \bmod 8 = 5$ | $92 \bmod 8 = 4$ | 4, 5, 6 |
   | 5 | $5 \bmod 8 = 5$ | $11 \bmod 8 = 3$ | $17 \bmod 8 = 1$ | 1, 3, 5 |

2. **Insert one by one.** Index 0 to 7.

   | After inserting | Bit array |
   |---|---|
   | (start) | 00000000 |
   | 12 | 01001010 |
   | 25 | 01011110 |
   | 30 | 01011110 (bits 4, 5, 6 already 1) |
   | 5 | 01011110 (bits 1, 3, 5 already 1) |

3. **Check 6.** $h_1 = 6$, $h_2 = 13 \bmod 8 = 5$, $h_3 = 20 \bmod 8 = 4$. Bits 6, 5, 4 are all 1, so the filter says "probably present".
4. **Check 55.** $h_1 = 7$, $h_2 = 111 \bmod 8 = 7$, $h_3 = 167 \bmod 8 = 7$. Bit 7 is 0, so the filter says "definitely not present".

</Steps>

<Answer>

Final array 01011110 (bits 1, 3, 4, 5, 6 set). **6** is reported present but was never inserted: a **false positive**. **55** is reported absent and really is absent: a **true negative**.

</Answer>

<Box kind="verify">

Union of all positions from step 1: \{1, 4, 6\} ∪ \{1, 3, 5\} ∪ \{4, 5, 6\} = \{1, 3, 4, 5, 6\}, matching the array. With 5 of 8 bits set, a random new element passes all three bits with chance about $(5/8)^3 \approx 0.24$, so a false positive like 6 is not surprising.

</Box>

</Sum>

**(iii) Discussion.** <Cite id="stream-counting-mmds-home" loc="§4.3" />

- **6 (false positive):** its three bits were set by other elements (4 and 6 by 12 and 30, 5 by 25, 30 and 5). Bits are shared, so collisions cause this.
- **55 (true negative):** a single 0 bit proves it was never inserted.
- **True positive:** neither of the two checks. Checking an inserted element such as 12 would be one. A Bloom filter has **no false negatives**.

**Conclusion:** a Bloom filter saves memory and can say "no" with certainty, but "yes" is only probable.
