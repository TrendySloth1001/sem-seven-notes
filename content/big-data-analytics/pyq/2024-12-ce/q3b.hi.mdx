**In simple words:** **Bloom filter** ek bit array hota hai jisme kai hash functions lagte hain. Element **insert** karne ke liye uske hash positions ke bits 1 kar do. Element **check** karne ke liye uski positions dekho: koi bhi bit 0 hai to wo **pakka nahi** hai set mein; sab 1 hain to wo **shayad** hai. <Cite id="stream-counting-wiki-bloom" /> <Cite id="stream-counting-gfg-bloom" />

<Sum>

<Given>

$m = 8$ bits, shuru mein sab 0 (positions 0 se 7). $h_1(x) = x \bmod 8$, $h_2(x) = (2x+1) \bmod 8$, $h_3(x) = (3x+2) \bmod 8$. Insert karo 12, 25, 30, 5. Check karo 6 aur 55.

</Given>

<Find>

final bit array, 6 aur 55 present bataye jaate hain ya nahi, aur kaunse results sahi hain.

</Find>

<Steps>

1. **Har element ko hash karo.** *Reason: ye wo bit positions hain jo wo set karega.*

   | $x$ | $h_1$ | $h_2$ | $h_3$ | Bits set |
   |---|---|---|---|---|
   | 12 | $12 \bmod 8 = 4$ | $25 \bmod 8 = 1$ | $38 \bmod 8 = 6$ | 1, 4, 6 |
   | 25 | $25 \bmod 8 = 1$ | $51 \bmod 8 = 3$ | $77 \bmod 8 = 5$ | 1, 3, 5 |
   | 30 | $30 \bmod 8 = 6$ | $61 \bmod 8 = 5$ | $92 \bmod 8 = 4$ | 4, 5, 6 |
   | 5 | $5 \bmod 8 = 5$ | $11 \bmod 8 = 3$ | $17 \bmod 8 = 1$ | 1, 3, 5 |

2. **Ek-ek karke insert karo.** Index 0 se 7.

   | Insert ke baad | Bit array |
   |---|---|
   | (start) | 00000000 |
   | 12 | 01001010 |
   | 25 | 01011110 |
   | 30 | 01011110 (bits 4, 5, 6 pehle se 1) |
   | 5 | 01011110 (bits 1, 3, 5 pehle se 1) |

3. **6 check karo.** $h_1 = 6$, $h_2 = 13 \bmod 8 = 5$, $h_3 = 20 \bmod 8 = 4$. Bits 6, 5, 4 teeno 1 hain, to filter kehta hai "probably present".
4. **55 check karo.** $h_1 = 7$, $h_2 = 111 \bmod 8 = 7$, $h_3 = 167 \bmod 8 = 7$. Bit 7 zero hai, to filter kehta hai "definitely not present".

</Steps>

<Answer>

Final array 01011110 (bits 1, 3, 4, 5, 6 set). **6** present bataya gaya par kabhi insert nahi hua tha: **false positive**. **55** absent bataya gaya aur sach mein absent hai: **true negative**.

</Answer>

<Box kind="verify">

Step 1 ki saari positions ka union: \{1, 4, 6\} ∪ \{1, 3, 5\} ∪ \{4, 5, 6\} = \{1, 3, 4, 5, 6\}, jo array se match karta hai. 8 mein se 5 bits set hain, to ek random naya element teeno bits pass kar jaaye iski chance lagbhag $(5/8)^3 \approx 0.24$ hai, isliye 6 jaisa false positive hairaan nahi karta.

</Box>

</Sum>

**(iii) Discussion.** <Cite id="stream-counting-mmds-home" loc="§4.3" />

- **6 (false positive):** iske teeno bits dusre elements ne set kiye the (4 aur 6 ko 12 aur 30 ne, 5 ko 25, 30 aur 5 ne). Bits share hote hain, isliye collision se ye hota hai.
- **55 (true negative):** ek akela 0 bit saabit kar deta hai ki ye kabhi insert nahi hua.
- **True positive:** in do checks mein se koi bhi nahi. 12 jaise inserted element ko check karte to wo hota. Bloom filter mein **false negative kabhi nahi** hota.

**Conclusion:** Bloom filter memory bachata hai aur "nahi" pakke se bol sakta hai, lekin "haan" sirf probable hota hai.

Exam mein English mein likho: "6 is a false positive and 55 is a true negative; a Bloom filter never gives a false negative."
