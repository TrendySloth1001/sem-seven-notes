**In simple words:** **RDBMS** (MySQL, Oracle) neat tables ko ek strong server pe rakhta hai aur SQL queries ka jawab jaldi deta hai. **Hadoop** ek framework hai jo kisi bhi type ka data bahut saari sasti machines pe store karta hai aur parallel process karta hai. Basic difference: RDBMS chhote ya medium **structured** data aur transactions ke liye bana hai, jabki Hadoop **bahut bade aur alag-alag type ke** data ko batch mein process karne ke liye bana hai. <Cite id="hadoop-ecosystem-gfg-hadoop-intro" /> <Cite id="hadoop-ecosystem-tp-hadoop-overview" />

| Point | Traditional RDBMS | Hadoop |
|---|---|---|
| Data type | Structured (tables, fixed schema) | Structured, semi-structured aur unstructured |
| Data size | Gigabytes se kuch terabytes | Terabytes se petabytes |
| Schema | Schema on write: pehle table design karo, phir load | Schema on read: file load karo, padhte time structure do |
| Scaling | Scale up (bada server), mehnga | Scale out (sasti nodes add karo) |
| Hardware | Mehnge high-end servers | Commodity hardware |
| Processing | SQL, indexed data pe tez | Batch jobs (MapReduce, Spark), bahut zyada throughput |
| Updates | Bar bar read aur write | Write once, read many times |
| Transactions (ACID) | Poora support | Isliye nahi bana |
| Fault tolerance | Alag se set-up chahiye | Built in (replication, task re-run) |

**Example:** bank account balance RDBMS mein rakhta hai kyunki har transfer exact aur turant hona chahiye. Wahi bank saalon ke web logs aur call recordings ka analysis Hadoop mein karta hai. <Cite id="big-data-intro-wiki-rdbms" /> <Cite id="hadoop-ecosystem-wiki-hadoop" />

**Conclusion:** structured data pe fast transactions ke liye RDBMS, bahut bade aur mixed data ke analysis ke liye Hadoop; dono aksar saath use hote hain.

Exam mein English mein likho: "An RDBMS handles structured data with a fixed schema and ACID transactions by scaling up, whereas Hadoop stores and processes structured and unstructured data in batches by scaling out on commodity hardware."
