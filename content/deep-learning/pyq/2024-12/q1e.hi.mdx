**In simple words:** pooling ek feature map ko chhota karta hai, har chhoti window ko ek number se summarize karke. Max pooling sabse badi value rakhta hai; average pooling mean rakhta hai. <Cite id="gfdl-ch9" />

**Ye kyun zaroori hai.** Kam values ka matlab later layers mein kam computation, aur feature ki chhoti shift se output zyada nahi badalta.

**Kaise kaam karta hai.** Ek window (aksar 2×2) aur stride (aksar 2, taaki windows overlap na karein) chuno. Use har channel pe slide karo aur har window ki ek value chhote output mein likho.

<Sum>

<Given>

ek 2×2 window ki values 1, 3, 5 aur 6 hain.

</Given>

<Find>

max-pooled aur average-pooled output.

</Find>

<Steps>

1. **Max:** sabse badi value 6 hai.
2. **Average:** values jodo, 1 + 3 + 5 + 6 = 15, phir 4 values se bhaago: 15 ÷ 4 = 3.75.

</Steps>

<Answer>

max pooling 6 deta hai, average pooling 3.75 deta hai.

</Answer>

<Box kind="verify">

Ulta multiply karo: 3.75 × 4 = 15, jo values ka sum hai. Sort karne pe values 1, 3, 5, 6 hain, to maximum 6 hai.

</Box>

</Sum>

**Types:** max pooling (sabse common), average pooling, aur global average pooling (poora map ek number ban jaata hai).

**Fayde:** 2×2 window aur stride 2 se values ek chauthaai reh jaati hain; chhoti shifts jhel leta hai; koi learnable weights nahi. **Nuksaan:** fine detail aur exact position kho jaate hain. <Cite id="keras-maxpool2d" /> <Cite id="mlm-cnn-pooling" />

**Conclusion.** Pooling important information ko chhote feature map mein rakhta hai.

Exam mein English mein likho: "Max pooling keeps the largest value in each window, which reduces the feature map size."
