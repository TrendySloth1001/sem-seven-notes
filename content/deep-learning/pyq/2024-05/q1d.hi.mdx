**In simple words:** undercomplete autoencoder mein code layer apne input se chhoti hoti hai. Wo sab kuch store nahi kar sakti, isliye sirf sabse important features rakhti hai, jaise poori film ko ek line mein batana. <Cite id="gfdl-ch14" />

**Definition.** Undercomplete autoencoder ek autoencoder (encoder, code, decoder) hai jiska code input se chhota hota hai. Ise bina labels ke train karte hain taaki output input ki copy ban jaaye.

**Ye kyun zaroori hai.** Narrow bottleneck se har detail ki exact copy banana mushkil ho jaata hai, isliye network ko wahi patterns seekhne padte hain jo matter karte hain.

**Ye kaise kaam karta hai.** Encoder input (jaise 784 pixels) ko ek chhote code (jaise 32 numbers) mein dabata hai. Decoder us code se input wapas banata hai. Training input aur output ke beech ka difference kam karti hai.

**Key points**

- Linear decoder aur squared-error loss ke saath ye wahi subspace seekhta hai jo PCA dhoondhta hai. Non-linear layers ke saath ye PCA ka generalization ban jaata hai. <Cite id="wiki-pca" />
- **Advantages:** simple hai, koi extra penalty nahi chahiye, aur compression deta hai.
- **Disadvantages:** bahut chhota code detail kho deta hai, aur bahut powerful encoder aur decoder phir bhi ratta maar sakte hain.

**Applications:** dimensionality reduction, image compression, feature extraction.

**Conclusion.** Chhota code hi restriction hai, isliye autoencoder bina kisi extra penalty ke data ka compact summary seekhta hai.

Exam mein English mein likho: "An undercomplete autoencoder has a code smaller than its input, so it learns a compressed summary."
