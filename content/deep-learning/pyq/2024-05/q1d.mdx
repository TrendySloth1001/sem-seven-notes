**In simple words:** an undercomplete autoencoder has a code layer smaller than its input. It cannot store everything, so it must keep only the most important features, like summing up a whole film in one sentence. <Cite id="gfdl-ch14" />

**Definition.** An undercomplete autoencoder is an autoencoder (encoder, code, decoder) whose code is smaller than its input. It is trained without labels to make its output copy its input.

**Why it is needed.** The narrow bottleneck makes it hard to copy every detail exactly, so the network is forced to learn the patterns that matter.

**How it works.** The encoder squeezes the input (for example 784 pixels) into a small code (for example 32 numbers). The decoder rebuilds the input from that code. Training reduces the difference between input and output.

**Key points**

- With a linear decoder and squared-error loss, it learns the same subspace that PCA finds. With non-linear layers it generalizes PCA. <Cite id="wiki-pca" />
- **Advantages:** simple, needs no extra penalty, and gives compression.
- **Disadvantages:** a code that is too narrow loses detail, and an encoder and decoder that are too powerful can still memorize.

**Applications:** dimensionality reduction, image compression, feature extraction.

**Conclusion.** The small code is itself the restriction, so the autoencoder learns a compact summary of the data with no extra penalty.
