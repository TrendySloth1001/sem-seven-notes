**In simple words:** an undercomplete autoencoder has a narrow middle layer, so it cannot copy its input and must keep only what is important. <Cite id="class-dl-chp3" loc="slide 13" />

**Definition:** an Undercomplete Autoencoder is an autoencoder in which the hidden layer (Bottleneck/Code) has fewer neurons than the input layer. Because of this smaller bottleneck, the network is forced to compress the data and keep only the important features. <Cite id="class-dl-chp3" loc="slide 13" />

**Why "undercomplete":** Code Size < Input Size. Example: input 784 neurons, bottleneck 64 neurons, output 784 neurons.

<Img id="class-autoencoders-under-architecture" caption="Undercomplete autoencoder: 784 → 64 → 784, with the goal Input ≈ Output using fewer neurons." />

**How it works:** (1) the input enters the encoder, (2) the encoder compresses the information, (3) the bottleneck stores only important features, (4) the decoder reconstructs the input, (5) the loss is calculated, (6) the weights are updated by backpropagation. <Cite id="class-dl-chp3" loc="slide 13" />

**Advantages:** learns meaningful features, compresses data efficiently, prevents simple copying, reduces overfitting. **Disadvantages:** a too-small bottleneck may lose important information, and the bottleneck size must be chosen carefully. <Cite id="class-dl-chp3" loc="slide 14" />

**Uses:** image compression, feature extraction, dimensionality reduction. The textbook adds that it has no explicit regularization term, so only the small hidden layer stops it from memorizing. <Cite id="class-dl-m3" loc="p. 15" />

**Conclusion:** the narrow bottleneck forces the network to learn, not memorize.
