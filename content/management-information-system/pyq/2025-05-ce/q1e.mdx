**In simple words:** the traditional SDLC is slow and rigid: users see the system only at the end, and late changes are costly. So some tools and methods are added to make development faster, cheaper and closer to what users want. <Cite id="it-impact-society-rainer-iis7" />

**Tools that augment the SDLC**

1. **Prototyping:** build a quick, small working model, show it to users, take feedback and improve it. It finds misunderstandings early, like a sample flat shown before the building is built. <Cite id="note-sdlc-wiki-prototyping" /> <Cite id="note-sdlc-gfg-prototype" />
2. **Joint Application Design (JAD):** a workshop where users, managers and analysts sit together and agree the requirements in a few days instead of many separate interviews. <Cite id="note-sdlc-wiki-jad" />
3. **Rapid Application Development (RAD):** combines prototyping, JAD, CASE tools and reusable parts in short time-boxes, to deliver in weeks or months. <Cite id="note-sdlc-wiki-rad" />
4. **CASE tools:** software that helps developers draw diagrams, keep requirements in one repository, generate code and documentation. <Cite id="note-sdlc-wiki-case" />
5. **Object-oriented and component-based development:** build the system from reusable objects and components.
6. **Agile methods:** build in short cycles, deliver a working part each time and welcome change.
7. **End-user development:** users build small applications themselves with spreadsheets or low-code tools.

| Tool | Main benefit | Main limit |
|---|---|---|
| Prototyping | Early user feedback | Users may mistake it for the final system |
| JAD | Fast agreement | All key people must be free together |
| RAD | Fast delivery | Not for very large systems |
| CASE | Less manual work | Costly; needs learning |

**Conclusion:** these tools fix the slowness of the SDLC without removing its discipline.
