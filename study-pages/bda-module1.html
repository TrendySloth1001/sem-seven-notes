1. Characteristics and V's of big data

2023-12-ce Q1b · 5m2023-05-ce Q1c · 5m2024-05-ce Q1b · 5m2025-05-ce Q1a · 5m2024-05 Q1a · 5m2024-12 Q1a · 5m2025-12-ce Q5b · 10m
Write this (5 marks)

Definition: Big data is data that is too large (volume), arrives too fast (velocity) and is too varied (variety) for a traditional database to store and process. It is described by its V's: 3 V's are classic, 5 V's add veracity and value.

  • Volume = the amount of data (terabytes to petabytes).
  • Velocity = the speed at which data is created and must be processed (often real time).
  • Variety = many formats: structured, semi-structured, unstructured.
  • Veracity = how correct and trustworthy the data is (noise, spam, fake data).
  • Value = the useful result we get from the data.

Example table (social media site)

VMeaningSocial media example
VolumeHow much dataMillions of users upload text, photos, videos daily: petabytes
VelocityHow fast it arrivesLikes, comments, messages every second; feed must update at once
VarietyHow mixedText, emoji, image, video, audio, location, friend links
VeracityHow reliableFake accounts, spam, bots, rumours
ValueHow usefulRecommendations, targeted ads, trend and abuse detection

Add for 10 marks

  • Types of data (variety): structured (fixed rows and columns, bank records), semi-structured (tags or keys: JSON, XML, logs), unstructured (no format: photos, video, posts).
  • Variability (extra V): the meaning of data changes with context, for example the same word means different things in different posts.
  • Two case studies (if asked "justify with case studies"):
    Case studyVJustification
    Stock exchangeVelocityOrders arrive in huge numbers every second; a price signal one minute late is useless, so it is processed as a stream
    Hospital recordsVarietyOne patient has table data, doctor notes, X-ray images, monitor readings; one fixed table cannot hold all
    Social mediaVolumeEvery photo and video of every user is stored, growing to petabytes
  • Advantages: better decisions, personalised offers, fraud detection, prediction. Challenges: storing and moving huge data, poor quality (veracity), privacy.

Fit it to the question

  • "Four characteristics ... elaborate with respect to social media": volume, velocity, variety, veracity with the table above.
  • "3 V's + two case studies with justification": three V's, then the case-study table (stock exchange, hospital).
  • "Explain 5 V's" / "Big data and its characteristics": definition, all five with diagram, one example each. Do not miss veracity and value.

Tips: always draw the V's diagram and give a one-line example for each V. Do not confuse velocity (speed of arrival) with variability (changing meaning).

Sources: Wikipedia "Big data"; IBM "What is big data"; NIST Big Data Interoperability Framework (definitions); class notes Module 1.

2. Traditional database vs big data (RDBMS vs Hadoop)

2023-12 Q1b · 5m2025-05 Q1a · 5m2023-12-ce Q1a · 5m
Write this (5 marks)

Traditional database (RDBMS): stores structured data in tables with a fixed schema on one server, queried with SQL. Big data: data too large, fast and varied for that model, so it is stored and processed on a cluster (for example with Hadoop).

DataStructured tables onlyAny format

Why they work together: a bank keeps account balances in an RDBMS (exact, instant) and studies years of transactions in Hadoop for fraud. Hadoop does not replace the RDBMS.

Schema on write: design table, load data that fits, query. Schema on read: load any file as it is, give structure when reading, analyse.

Fit it to the question

  • "Compare traditional database and big data" / "traditional data and big data": one line each, then the first table (8 to 10 rows).
  • "Basic difference between RDBMS and Hadoop": write the second table and mention schema on read, scale out, commodity hardware.

Tips: the table is the whole answer. The three keyword pairs: structured vs unstructured, scale up vs scale out, schema on write vs schema on read.

A big data architecture is a layered design that collects data from many sources, stores it on a cluster, processes it in parallel and shows the result. Layers: data sources, ingestion, storage, processing, analysis, visualization, with security and management across all layers.

4. What is Hadoop: core components and architecture

2023-12 Q1a · 5m2024-05-ce Q1a · 5m2024-12 Q4a · 10m2022-12-ce Q4a · 10m
Write this (5 marks)

Apache Hadoop is a free, open-source Java framework for storing very large data across a cluster of commodity computers (HDFS) and processing it in parallel (MapReduce), with YARN managing resources. Its design comes from two Google papers: the Google File System and MapReduce.

Why needed: one machine cannot store terabytes; reading them through one disk takes hours; a big special machine is costly and a single point of failure. Hadoop uses many cheap machines.

Four core components: 1. Hadoop Common (libraries), 2. HDFS (storage), 3. YARN (resources and scheduling), 4. MapReduce (processing).

Why it matters: scalable, low cost, fault tolerant, flexible (any data type).

HDFS: the storage component (add for 10 marks)

  • A file is cut into blocks (128 MB); each block is kept on 3 nodes (replication 3). Write once, read many.
  • NameNode (master): keeps metadata (file names, which DataNodes hold each block). Does not store data.
  • DataNodes (slaves): store the blocks, send heartbeats and block reports to the NameNode.
  • Replica placement: copy 1 on the writer's node, copy 2 on another rack, copy 3 on another node of that rack, so losing a rack loses no data.

MapReduce: the processing component

  1. Input split: input divided into splits, one map task per split, preferably on the node that holds the block (data locality).
  2. Map: emits key-value pairs, for example (to,1), (be,1).
  3. Shuffle and sort: pairs with the same key go to the same reducer, sorted by key. An optional combiner adds counts on the map side first.
  4. Reduce: combines the values of a key: (to,[1,1]) gives (to,2).
  5. Output is written to HDFS.

YARN (Hadoop 2 onwards)

ResourceManager (master) shares CPU and memory; NodeManager (per node) runs containers; ApplicationMaster (per job) runs the job's tasks. In Hadoop 1 the single JobTracker and TaskTrackers did this, but the JobTracker was a bottleneck.

5. Hadoop ecosystem diagram and components

2023-12 Q2a · 10m2025-05 Q2a · 10m2025-05-ce Q6a · 10m2025-12-ce Q2a · 10m2024-12-ce Q4b · 10m (any two)
Write this (core, 5 marks)

The Hadoop ecosystem is the group of tools that work with the Hadoop core (HDFS storage, YARN resource management, MapReduce processing). The core stores and processes data, but raw MapReduce in Java is hard, and a real project also needs loading, querying, coordination and scheduling. Each tool fills one such gap.

ComponentLayerJob in simple words
HDFSStorageStores big files as replicated blocks across the cluster
YARNResource managementShares CPU and memory between applications
MapReduceProcessingBatch processing in map, shuffle, reduce steps
HiveQuerySQL-like queries (HiveQL) on HDFS data, turned into jobs
PigScriptingData-flow scripts in Pig Latin instead of long Java
HBaseNoSQL databaseColumn database on HDFS for fast single-row read and write
SparkProcessingFast engine that keeps data in memory
MahoutMachine learningRecommendation, clustering, classification
ZooKeeperCoordinationConfiguration, naming, locks, leader election
OozieSchedulingRuns a chain of jobs in order
SqoopIngestionBulk copy between RDBMS and HDFS
FlumeIngestionCollects streaming logs into HDFS
AmbariManagementWeb tool to set up and monitor the cluster

Conclusion: the core gives storage and processing; the ecosystem tools add ingestion, query, speed and management, so Hadoop becomes a complete big data platform.

For "explain any two" (write need, how it works, example)

  • Hive: analysts know SQL, not Java. Write SELECT city, COUNT(*) FROM users GROUP BY city; Hive turns it into distributed jobs. Good for batch analysis, not quick single-row lookups.
  • HBase: HDFS is poor at reading one record quickly. HBase stores rows in tables with column families, sorted by row key, on top of HDFS, modelled on Google's Bigtable. Example: fetch one user's profile in milliseconds.
  • Pig: a short Pig Latin script (load, filter, group, join) replaces long Java code.
  • Spark: keeps data in memory, so iterative jobs and machine learning are much faster than MapReduce.
  • Sqoop and Flume: Sqoop copies tables from MySQL or Oracle into HDFS; Flume collects server logs as they are produced.
  • ZooKeeper, Oozie: ZooKeeper keeps the distributed tools in agreement (locks, leader election); Oozie runs a workflow of jobs in the right order.

Fit it to the question

  • "Draw the Hadoop ecosystem and explain components" (10m): Fig 5.1, the component table (one line each), conclusion.
  • "Explain Hadoop ecosystem in detail" (10m): all of the above plus the "any two" details and Fig 5.2.
  • "Draw the ecosystem and explain any two components" (10m): draw the diagram, then explain only two (Hive and HBase are safe).

Tips: name the layer and one-line job of each tool; that is what gets the marks. For "any two", give definition, need, working and example for those two only. Some tools (Sqoop) are now retired, but exams still ask for the classic list.

Sources: Apache project pages (Hadoop, Hive, Pig, HBase, Spark, ZooKeeper, Oozie, Sqoop, Flume, YARN); GeeksforGeeks Hadoop ecosystem; class notes Module 1.

6. Advantages and limitations of Hadoop

2024-12 Q1c · 5m (limitations only)2025-05 Q1b · 5m (both)
Write this (5 marks)

Hadoop is scalable, low cost, fault tolerant and handles all data types, but it is poor for small files, real-time answers, iterative jobs and transactions.

AdvantagesLimitations
Scalable: add nodes to add storage and speedSmall files problem: every file and block is an object in NameNode memory
Low cost: commodity hardware, free softwareBatch only: jobs take seconds to minutes to start, no real time (high latency)
Fault tolerant: 3 copies of blocks, failed tasks re-runSlow for iterative work: disk writes between MapReduce steps
Any data type: schema on readNo in-place updates or transactions: write once, read many
Fast on huge data: parallel work and data localityHard to program: long Java code for simple jobs
Large ecosystem and communityOverheads: 3x storage, NameNode weak point, security needs set-up

Limitations with the reason (write the reason always)

  1. Small files: each file, directory and block is an object (about 150 bytes) in the NameNode's memory, so millions of tiny files exhaust it, and each file also gets its own short map task.
  2. Batch and high latency: not for real-time answers or streams.
  3. Iterative jobs: MapReduce writes to disk after every step, so machine learning and graph algorithms that loop many times are slow. Spark keeps data in memory.
  4. No updates or transactions: HDFS only appends; a poor fit for banking-type updates.
  5. Hard programming model: everything must be forced into map and reduce.
  6. NameNode: single point of failure in Hadoop 1; Hadoop 2 added a standby NameNode but it needs extra set-up.
  7. Storage overhead: 3 copies means 200% extra storage. Hadoop 3 erasure coding gives the same safety with about 50% overhead.
  8. Security and administration: weak by default unless Kerberos is set up; large clusters need skilled people.
Use Hadoop forDo not use Hadoop for
Log analysis, search indexesSmall data that fits one server
Recommendation and big analyticsReal-time answers, quick lookups
Cheap archiving of huge dataBanking-type updates and transactions

Fit it to the question

  • "Write the limitations of Hadoop" (5m): only the right column, 5 to 6 points with a one-line reason each, plus Fig 6.1. No advantages.
  • "Advantages and limitations of Hadoop" (5m): the full two-column table, about 4 or 5 of each, then one conclusion line: low-cost scalable platform for batch analysis of very large data.

Tips: give a reason with every limitation (for example "small files: NameNode keeps metadata in RAM"). Mention Spark, Hive and HA NameNode as fixes. Do not write "slow" alone: write "high latency batch".

Sources: GeeksforGeeks and IBM on Hadoop; Apache HDFS design; Cloudera "small files problem"; Hadoop 3 erasure coding docs; class notes Module 1.
